## 4. Развёртывание

МедЗапись записывает пациентов на приём в клиники сети.
Система работает в двух центрах обработки данных: ЦОД-1 (основной) и ЦОД-2 (резервный).
Таблицы этого раздела перечисляют все узлы системы; других узлов нет.

### 4.1 ЦОД-1 (основной)

| Узел | Назначение |
| :--- | :--- |
| WAF | единственный вход из Интернета |
| VPN-шлюз | вход для рабочих мест регистратуры |
| Балансировщик | HAProxy, пара active/passive |
| Узлы приложения | app-01, app-02, app-03 |
| СУБД основная | PostgreSQL 15, данные приложения |
| Сервер мониторинга | Zabbix |

Пациенты открывают сайт записи по HTTPS через WAF.
Рабочие места регистратуры подключаются через VPN-шлюз.
WAF и VPN-шлюз передают запросы балансировщику.
Балансировщик распределяет запросы между узлами приложения.
Активный узел балансировщика принимает запросы; пассивный принимает их при отказе активного.
Узлы приложения не хранят состояния: любой узел обслуживает любой запрос.
Узлы приложения читают и пишут данные в СУБД основную.
Сервер мониторинга опрашивает все узлы обоих ЦОД.

### 4.2 ЦОД-2 (резервный)

| Узел | Назначение |
| :--- | :--- |
| СУБД резервная | асинхронная потоковая репликация от основной, отставание до 5 с |
| Сервер резервных копий | снимает копии СУБД основной каждые 6 ч, хранит их 14 дней |

В ЦОД-2 нет узлов приложения. СУБД резервная принимает только чтение, пока её не продвинут.

### 4.3 Отказ ЦОД-1

Автоматического переключения нет. При отказе ЦОД-1 дежурный вручную продвигает резервную СУБД
и переключает DNS.
Перед продвижением дежурный сверяет отставание резервной СУБД по данным мониторинга.
Цели восстановления для всей системы: RTO 1 ч, RPO 15 мин.
