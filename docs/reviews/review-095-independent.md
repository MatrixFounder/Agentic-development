# Review — Design Spec 095, rev 3

## Verdict

Rev 3 is **not ready to enter Phase 2**, and `§8.1 "Open questions: none"` / `§3 "decision-complete"` are both premature — not because decisions are open, but because three decisions (D1 cat. 2, D1 cat. 3, and implicitly S2's safety argument) rest on evidence that does not hold, and the one rule that makes Component A worth its cost cannot fire. The smallest set of changes that would make it ready: **(1)** replace R3's `default_max` digit-match with a machine-resolvable anchor and prove it on a negative fixture (frontmatter `3` over prose `2` must FAIL) — as written R3 passes unconditionally on every one of the 23 workflows, verified; **(2)** correct S2 by enumeration (`check_prompt_references.py:17` is a second CI-gating reader, and `smoke_workflows.py:36,40` does *not* skip frontmatter) and restate the invariant as a claim about parsers; **(3)** define a rule-legal Phase-2 representation for the six A.1 loops whose prose bound does not exist until Phase 3, and replace the Phase-2 exit gate ("WARN list matches Appendix A exactly") with a checked-in expected-output fixture — the current gate compares a warn list to a 24-row decision inventory and would compare an *empty* warn list against it; **(4)** give `framework-upgrade` an Appendix-A category (it is the only one of 23 workflows with none, and its two loops at `:19`/`:27` are real and unbounded), and correct the double-counted rows so `override: allowed` has a justification; **(5)** re-derive §1.2 by hand over the three invocation spellings the repo actually uses. Items 1–3 are rework of §4/§5; items 4–5 are corrections. Separately, the ship order should be reopened — see **Scope challenge**.

## Design gaps

### Theme A — the grammar cannot express what §1 says is the problem
*Decision forced: does rev 4 extend §4.3/§4.5, or does §1 drop the properties the grammar cannot carry?*

- **§4.4 contradicts R1.** R1 permits `default_max: null` with `gated_by: hitl`; §4.4's `allowed` row permits null only "with `judgment_terminated`". `allowed` + `gated_by` + null is legal under one and illegal under the other.
- **`binds` cannot re-scope a counter — property 3, the headline defect.** A.2 row 5 encodes the vdd-enhanced re-scope as a bind carrying `scope: per_run`, but §4.5's `binds` mapping is `{max, exit_bar?}` — there is no `scope` key. The same phenomenon is then also encoded as an own-loop (row 11). One of the two must go.
- **`calls[]` has three missing kinds.** (a) *Fragment delegation* — `.agent/workflows/vdd-05-run-full-task.md:15` delegates to `vdd-03-develop.md` **Step 3** only; `calls: [vdd-03-develop]` would falsely imply the whole workflow runs and would make R2/R5 reason over a call that never happens. (b) *Flag-suppressed callee loop* — `.agent/workflows/full-robust.md:32-33` passes `--no-fix`, which `.agent/workflows/vdd-multi.md:184` says skips Phase 3 entirely; no key records this, so the callee's declared loop appears live. (c) *Escalation/handoff* — `light-01-start-feature.md:41`, `.agent/workflows/light-02-develop-task.md:58`. Suggest `kind: invoke|escalate`, `args:`, `suppresses: [loop_id]`, `partial: "Step 3"` — and document them against those exact edges so Phase-2 authors do not re-decide 23 times.
- **No rule closes the `binds` → callee direction.** R9 forbids binding a `forbidden` loop, but nothing requires a `binds` key to resolve to any `loops[].id` the callee declares. Add R12 (error, Phase 2) — the validator already loads every file for R4/R5, so it is free.
- **`judgment_terminated` + `exit_bar` is an unpoliced escape hatch.** R10 requires only a *non-empty* string. `exit_bar: "until done"` converts any unbounded loop into a compliant declaration. All three A.1 cat-1 loops could be closed this way — their prose already says "repeat the review", which is judgment-terminated phrasing. Either require `exit_bar` to be a verifiable citation (same mechanism as the fixed R3), or require a numeric backstop, which §4.3's own wording implies ("any numeric cap is a backstop, not the mechanism"), with `vdd-multi` as the single documented exemption under S10.

## Scope challenge

**The strongest case: Components A and B should not ship, and Phase 3 should ship alone.**

The defect §1.1 names is real, small, and localised: six unbounded retry loops in five files — `.agent/workflows/vdd-01-start-feature.md:15` and `:19`, `.agent/workflows/vdd-02-plan.md:15`, `.agent/workflows/vdd-03-develop.md:24`, `.agent/workflows/vdd-adversarial.md:44`, `.agent/workflows/security-audit.md:33` — each closable with one sentence in the idiom already used at `.agent/workflows/01-start-feature.md:11-12`. That is roughly 12–15 added lines across five files, one commit, `/light`-sized. It closes §1.1 **completely**: the spec's own Appendix A decides the remaining two unbound loops (`vdd-multi`, `iterative-design`) as *no change*.

Against that, Phase 2 proposes ~24 loop blocks at the §4.7 worked example's ~8 lines each, plus ~19 `calls` edges and 23 headers — roughly 320 added lines onto a 1,279-line workflow corpus (+25%) — plus a 10-rule validator with graph cycle detection, YAML-subset parsing, `--json`/`--strict` and four exit codes (`smoke_workflows.py` is 80 lines for two rules; realistically 350–500 plus tests), plus a fifth CI job. Call it 700–850 new lines to protect ~15. And the rule set does not survive inspection: R3 vacuous, R2 and R5 unfireable, R8 unimplementable, R4's advertised gap left open, R1/R6/R7/R9/R10 checking the declaration against itself. §4.6's own test — "declaring data that nothing reads is the over-engineering this design otherwise avoids" — condemns `loops[]` at Phase 2 exactly as it condemns `gates[]`. The spec applies the test to one and exempts the other without argument. §7's "Phase 2 is the highest-value / lowest-risk step and can stand alone indefinitely" inverts the truth: Phase 3 is the part that stands alone; Phase 2 is the part that can be dropped with no loss.

**The counter-argument, stated fairly.** §1.3 is right that prose is not enforcement, and `.agent/workflows/full-robust.md:8-9` proves it — that file *asserts* "Every retry loop is **bounded**" while three of its four sub-workflows' loops are not, and nothing caught it. Six new prose sentences are six new copies of the same unenforced invariant, and the VDD copy-drift in §1.1's table happened *precisely because* nothing checked; a fix with no checker guarantees recurrence when the next VDD variant is forked. Component A's real product is also not the numbers — it is the **inventory**, which cost a human audit, and frontmatter is how that audit survives the next author. There is a genuine asymmetry: prose bounds decay silently, declarations can be diffed.

**But the counter only bites if something reads the declaration and can disagree with the prose** — and that is exactly R3, which as specified fires on nothing (blocking finding 1), and R6, which cannot detect an undeclared loop (finding 4). So the counter reduces to: *fix R3 first, then A+B are worth it*. Which is the same instruction, in a different order. Recommended sequence: (1) Phase 3 alone, now, as `/light` — six sentences, five files, §1.1 closed; (2) two one-line fixes as separate commits — `smoke_workflows.py:19`'s `CALL_RE` and `check_prompt_references.py:21`'s dead regex, both in jobs that already run and both worth more than Phase 2 delivers; (3) reopen A+B in rev 4 with a working R3, a negative fixture, and a stated answer to "what defect does this detect now that §1.1 is gone?"
