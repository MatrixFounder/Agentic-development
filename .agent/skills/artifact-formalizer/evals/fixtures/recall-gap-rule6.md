# Очередь повторной доставки уведомлений

## 1. Границы

В границах: очередь повторов и порядок её обхода. Вне границ: транспорт push-уведомлений, за
который отвечает сервис доставки.

## 2. Требования

| ID | Требование | MVP? |
| :--- | :--- | :--- |
| R1 | Неудачная доставка попадает в очередь повторов с меткой времени | Y |
| R2 | Число повторов одного уведомления не превышает пяти | Y |
| R3 | Интервал между повторами удваивается от 30 секунд | Y |

### 2.1 Детализация

**R1.** Манжета повторов принимает уведомление, доставка которого вернула код 5xx.

**Почему.** Код 4xx означает ошибку запроса, и повтор вернёт тот же результат.

**R2.** Шестая попытка не выполняется; уведомление переводится в статус `failed`.

**Почему.** Пять попыток при удвоении интервала покрывают 15 минут недоступности.

**R3.** Просека обхода читает очередь по возрастанию метки времени и берёт первые 200 записей.

**Почему.** Партия в 200 записей укладывается в окно блокировки 2 секунды.

## 3. Отказы

| Условие | Исход | Обнаруживается |
| :--- | :--- | :--- |
| Очередь недоступна | доставка выполняется без записи повтора | T4 |
| Метка времени в будущем | запись пропускается и логируется | T5 |

## 4. Обязательства по тестам

- T1 — ответ 503 → запись появляется в очереди; не проходит при фильтре только по 500.
- T2 — пять неудач подряд → статус `failed`; не проходит при границе в шесть.
- T3 — 500 записей в очереди → обработано 200 за проход.
